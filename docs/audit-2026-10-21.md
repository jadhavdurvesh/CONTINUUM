# Production-readiness audit (2026-10-21)

Baseline: everything compiled and all existing tests passed, so the issues below were found by review, not by failing builds.

## Fixed

| Area | Problem | Fix |
|---|---|---|
| Vercel `run-step` | Check-then-update was not atomic: two requests could run the same session twice (double model spend, duplicate messages). | Compare-and-swap `PATCH ... status=eq.queued` with `return=representation`; 409 if nothing was claimed. |
| Vercel `run-step` | History query used `order=asc&limit=40` then took the last 12, so after 40 messages the model saw the *oldest* turns. | `order=desc&limit=12`, reversed. |
| Vercel `run-step` | Expired token / RLS denial surfaced as HTTP 502. | Typed errors map to 401 / 403. |
| Vercel `run-step` | A killed function left sessions `running` forever. | Runs older than 5 min are reclaimable. Provider calls share a deadline below `maxDuration`. |
| Vercel | `api/agents/cors.ts` was deployed as a public endpoint (no default export → 500s). | Helpers moved to `api/_lib/` (ignored by Vercel). |
| Vercel CORS | Production origin hard-coded. | `CONTINUUM_DASHBOARD_ORIGIN` (comma list) + Vercel system URLs. |
| Proposal validation | Agents could write `.github/`, `.husky/`, `.vscode/` etc. — files that execute code on the next push/commit/test. Duplicate and control-character paths accepted. | Blocked in Vercel, worker and native app; duplicates/control chars rejected; fenced/prose-wrapped JSON tolerated. |
| Worker | Prompt was built with a literal backslash-n instead of newlines (14 places), degrading every local agent run. | Fixed + test. |
| Worker | `pytest --basetemp=<dir>` passed the path check and **deletes that directory**; `-p/-c/-o/--rootdir` also reachable. | Strict pytest flag/path allowlist + tests. |
| Worker | Child processes inherited `CONTINUUM_WORKER_TOKEN` and Supabase settings. | `CONTINUUM_*` scrubbed from child env. |
| Native app | Apply dialog showed only a file count. | Lists the paths being written. |
| Supabase | A member could move a session to another project or reassign `requested_by`. | New migration `202610210001` (also appended to `setup_all.sql`). |
| Invite function | Only the first 1000 accounts were searched, so existing users beyond that failed to invite; unpinned `esm.sh` import; wildcard CORS; no UUID check. | Paginated lookup, pinned `npm:` import, optional `CONTINUUM_ALLOWED_ORIGIN`, validation. |
| Web | Worker token stored in `localStorage`. | Token moved to `sessionStorage`. |
| Web | 1.16 MB single JS bundle; no security headers. | Manual chunks; headers in `vercel.json`. |
| CI | No lockfile, `npm install`, API functions only transpiled, secrets exposed to every installer step. | `package-lock.json` + `npm ci`, API type-check + tests, secrets scoped to one step, timeouts. |

## Still open (needs a design decision)

1. **Forgeable agent messages.** RLS lets any project member insert `role='assistant'` rows, and "Apply" trusts the latest one. A malicious collaborator could plant a proposal that rewrites a file the owner then runs. Real fix: insert agent messages server-side (service role or a `SECURITY DEFINER` RPC) and sign proposals.
2. **No rate limiting / quotas** on `run-step` (per user or project).
3. **Installers are unsigned** (SmartScreen warnings, no tamper evidence) and there is no release/versioning pipeline.
4. **Allowed CLI commands run repo scripts** (`npm test` etc.), which is inherent; treat the worker as trusted-repo only.
5. No end-to-end tests for the cloud flow; Theia path is still unvalidated per the migration plan.
